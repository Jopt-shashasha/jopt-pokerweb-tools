# 手動返信の送信者記録

Harness のチャット画面・友だち詳細から手動送信したメッセージには、サーバーが認証済みスタッフの ID と送信時の名前を保存する。本文の送信者名やチャット担当者設定は利用しない。

各スタッフは「スタッフ管理」で作成した自分専用の API Key でログインする。環境変数 API_KEY での送信は「共通オーナーキー」と表示する。共通 Key の利用者個人は区別できない。

顧客の LINE 画面では従来どおり公式アカウント名が表示される。スタッフ名は Harness 内だけに表示し、LINE 送信内容には追加しない。

messages_log.sender_staff_id / sender_staff_name はスナップショットとして保持し、スタッフを改名・削除しても過去の記録を失わない。LINE 送信成功後にのみ記録する。既存レコードや外部送信の送信者は推測しない。source=manual で名前がない場合は「送信者：不明」。自動送信をスタッフ送信として表示しない。

既存環境は packages/db/migrations/074_manual_message_sender.sql を一度だけ適用してから Worker をデプロイする。新規構築用の schema.sql と bootstrap.sql にも同じ nullable 列を含む。2026-10-26 JST に会社 Cloudflare の D1 に適用し、適用時の 248 行が保持され、外部キー検査に問題がないことを確認した。

検証：異なるスタッフ、送信者偽装、チャット担当者との差、改名後の名前保持、共通 Key、友だち詳細送信、旧記録、送信失敗。実ユーザーへのテスト送信は行っていない。
