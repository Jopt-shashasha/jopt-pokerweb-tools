# 業務ポータル：CLAUDE向け画面プロトタイプ制作依頼

## 今回の依頼

企画書は既読として、詳細な本番実装ではなく、リーダーが実際に触って方向性を判断できる軽量プロトタイプを1案制作してください。画面内の言語は日本語です。

Codexも別案を制作します。同じ画面の色違いではなく、情報の配置・利用の入口が異なる2案を比較します。

## 2案の分担

| | Codex案 | CLAUDE案（今回） |
|---|---|---|
| 方向性 | 検索中心型 | 業務ワークスペース型 |
| 利用の入口 | 資料・ツールを検索して探す | 日々使うもの・自分の仕事から入る |
| ホームの主役 | 検索、分類、一覧 | 常用ツール、保存済み、最近使った資料 |
| 情報構成 | 検索→絞り込み→結果→詳細 | ワークスペース→資料・ツール→必要時に検索 |

CLAUDE案では、検索欄を大きく置いた一覧画面を主役にせず、業務の入口として使うホームを設計してください。検索機能は残してください。余白・文字組み・色・ナビゲーションも独自に設計して構いません。

## 共通の確定事項

- AIFACTとJOPT dropの機能を受け継ぐ、別の新しい業務ポータルを作る。
- 既存2サービスを直接改修する方式ではない。ソースコードの再利用は可能。
- 既存リポジトリ・稼働中システムは変更しない。PRなしのマージは禁止。
- ログインは既存と同じGoogleアカウント方式。Codexをログイン手段にはしない。
- 資料・ツールの検索、セクション・大会／開催回・タグによる分類。
- 自分の資料、保存済みの資料を扱う。
- リンク登録とHTMLアップロードの入口をひとつのポータルに用意する。
- 共有範囲は全社共通／指定アカウントを想定。
- 成果物ごとの利用ガイド（MD）の生成・保存・登録は不要。画面にも追加しない。
- AIニュースをホームに表示する。
- Codexからポータルを利用した際、最新のAIニュースをCodex側にも提供する。画面を開かなくても情報が届く方向性。
- 配信・保存基盤は未確定。Cloudflare固定ではなくChatGPT Siteも候補。

## 今回体験できる範囲

1. ホームから資料・ツールを選ぶ。
2. キーワード検索と分類で絞り込む。
3. 資料の詳細を開き、用途・分類・共有範囲を確認する。
4. 保存済みへの追加・解除を試す。
5. リンク登録／HTMLアップロードを選び、入力して登録完了まで体験する。
6. Codex連携時に資料と最新ニュースが届く様子を、簡単なプレビューで確認する。

すべて例示データで構成し、実Google認証・既存DB・実アップロード・MCP接続は実装不要です。誤認を防ぐため「画面確認用／サンプルデータ」を明示してください。登録や保存はブラウザ内で完結して構いません。

AIニュースの見出しは表示例と明示し、実際の最新報道として扱わないでください。Codex連携もプレビューであることを明示してください。

## データの共通題材

比較しやすいよう、以下のような業務資料を使ってください。実在する資料の内容や実績は創作しないでください。

- Voucher関連資料：カスタマー、JOPT、Voucher
- Ticket管理シート：カスタマー、JOPT、Ticket
- 大会運営マニュアル：トーナメント、JOPT、運営
- 配信用クリエイティブ：クリエイティブ、SPADIE、メディア
- 搬入チェックリスト：ロジスティックス、JOPT、会場
- 企画書テンプレート：マーケティング、共通、企画

## 制作上の境界

- 1案で十分。複数テーマ切替や比較管理画面は不要。
- パソコン中心で制作し、スマートフォンでも主要操作ができるようにする。
- 未合意の業務機能（タスク管理、承認ワークフロー、KPI管理、チャットなど）は追加しない。
- 正式コードの保存先は `D:\GitHub\jopt-pokerweb-tools` 配下。着手前にユーザーへ具体的な保存場所を報告する。
- Codexは `web/gyomu-portal-prototypes` を使用するため、同じファイルを編集しない。CLAUDE案は別ディレクトリにする。
- 現段階で既存2リポジトリのダウンロードや改修は不要。
- Git commit・push・マージやアクセス範囲の変更は、ユーザーの指示なく実行しない。

## 受け入れ基準

スクリーンショットだけでなく、検索・詳細・保存・登録を実際に操作できること。リンクまたは起動方法と、試せる操作・未接続の機能を簡潔に報告してください。
