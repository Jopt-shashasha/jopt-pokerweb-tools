# JOPT Memory

Basic Memory はローカル Markdown のインデックスと MCP による読み書きを提供する。この Skill は、いつ使うか、ノートに何を書くか、どう検収するかを定める。現在の対象範囲は社員 PC 上のローカル知識ベースで、ローカル接続できるデスクトップ AI が共用する。ノートは社員の退職時の引き継ぎ資料であり、作業が終わったその時点で記録し、引き継ぎで「思い出せた分だけ」しか渡らない状態を防ぐことが目的。

## 読み取りと書き込み

- 既存の案件を引き継ぐとき、または過去の JOPT 業務について聞かれたときは、設定先の個人ナレッジベースを自分から検索する。案件の別名、成果物名、業務キーワードでノートを探し、結果・理由・未完了事項・原本を読み返す。必要に応じて原本を開いて確認する。ツールや記録が無い場合はその欠落を伝える。
- bm_search で `project` を指定して「projects が空」などの引数エラーが出た場合は、`project` を外して `projects=["<プロジェクト名>"]`（試行中は `["work-status-preview"]`）で再試行する。検索がエラーになっただけで「記録が無い」と判断しない。
- 判断基準：「1 年後にこの件で問題が起きたり誰かに聞かれたりしたとき、後任者は知る必要があるか？」必要なら、回答する前に自分から書き込む。作業の大小は問わない。
- 記録する：成果物・ファイル・コードの保存場所とその変更、実行・デプロイ方法（定期実行、トリガー、実行場所）、権限・共有範囲・アカウントの帰属、決定とその理由、ブロッカー・既知の問題・外部依存、後任者の次のアクション。
- 記録しない：一般的な質疑応答、結論の出ていない調査や議論、作業フォルダ内の一時ファイル・中間ファイル、下書き、既存マニュアル通りの定型作業（異常があった場合を除く）、ナレッジベースに既にあり新しい情報が無いもの。「新しい情報」かどうかはナレッジベースを基準に判断し、コードやファイルが変更されたかどうかでは判断しない。ナレッジベースに無い事実（実行方法、保存場所、権限など）を確認できたなら、何も変更していなくても記録する。
- 1 つの業務につき 1 ノート。正式な業務ノートは jopt-history/ に置く。まず検索し、同じ案件のノートがあれば bm_edit で現在の情報を更新して日付と変更内容を追記し、該当が無いときだけ bm_write で新規作成する。同じ作業の途中ではなく、作業の終わりにまとめて 1 回書く。JOPT の業務情報だけを記録し、私的な内容・顧客の個人情報・認証情報は除く。成功したらツールが返したノートの出典を確認し、失敗したら理由と書き込む予定だった差分を伝える。日付は Asia/Tokyo で日付のみ。会話中の「明日」「先週」などは具体的な日付に換算する。
- この Skill の本文は日本語で管理する。クライアントの常設指示は利用者がそのクライアントで使用する言語で用意する。ノート本文は現在の会話と同じ言語で書き、利用者から明示的な指定があればそれを優先する。既存ノートへの追記にも同じルールを適用する。
- このルール自体が利用者の事前承認である。条件に当てはまるときはそのまま書き込み、改めて確認しない。削除や他のノートの移動などその他の操作は、クライアント本来の承認手順に従う。
- 引き継ぎ用の項目は、案件名または成果物名、日付、現在の状態、主な結果または決定とその理由、後任者の次のアクション、成果物と原本。実際の変化に合わせて差分で更新する。

## ノートの構成

- 現在の状態：これは何か、成果物はどこにあるか、どう動いているか、権限とアカウント、既知の問題。変化があればその場で書き換えて常に最新にする。
- 主な経緯：転換点だけ「日付＋変化＋理由＋場所または出典」を 1 行追記する。例：決定、保存場所の変更、権限の変更、停止、訂正。誤字修正、書式の調整、途中の試行錯誤は記録しない。
- ノートを訂正・改名・移動・分類変更・停止したときは、そのノートに「日付＋何を変えたか＋理由」を 1 行追記し、元の内容は消さない。
- テストや演習の内容は jopt-tests/ に置き、タイトルに【模擬】を付け、タグに simulation を付ける。実際の業務の進捗には含めない。

## 成果物と原本

引き継ぎノートには必ず「成果物と原本」の節を設ける。正式名称、実際の保存場所、必要なアクセス条件を項目ごとに書く。今回が決定やブロッカーだけの場合は、確認できる社内の一次情報を出典として書く。原本がまだ作成中・所在不明のときは「要確認」と書き、何が未確認かを添える。ナレッジベースには場所だけを記録し、原本そのものは保存しない。正式な成果物は、先に社内リポジトリや会社のストレージに置いてから場所を記録する。

- 会社の Drive、共有ドライブ、業務システム：原本に直接たどり着ける社内 URL または UNC パスを優先する。複数の成果物が同じフォルダにある場合は、フォルダのリンクと各ファイルの正確なファイル名を書く。権限の範囲や申請窓口は、後任者に必要な場合だけ書く。
- リポジトリ：社内リポジトリの URL と相対パスを書く。その時点の成果物を再現する必要があるときは、コミット固定のリンクを使う。
- PC 内にしか無いもの：実際の絶対パスを書き、「この PC のみ」と明記する。別の PC への移行や退職時の引き継ぎが必要なら、会社側の保存先が未確定または移行待ちであることを書く。会社側に原本がある場合はそちらを優先する。
- 名前の変更、移動、共有先の変更をしたとき：元のノートで現在の入口を新しい場所に書き換え、「日付＋旧場所 → 新場所＋理由」を 1 行追記する。権限が変わった場合は合わせて記録する。旧場所は変更履歴として残す。
- 書き込む前に、作業結果、ファイルシステム、または許可された社内コネクタで場所を確認する。確認できない場所は「要確認」、後任者のアクセス権を確認できないときは「権限要確認」と書く。引き継ぎに必要な場所だけを書き、認証情報と顧客の個人情報は除く。

## 記憶ステータス行とクライアント内蔵メモリ

- JOPT 業務を扱うときは、毎回の回答の最後の行に「記憶：書き込み済み <ノート名または出典>」または「記憶：書き込みなし（理由）」を書く。会話が中国語の場合は「记忆：已写入 <笔记名>」「记忆：未写入（理由）」でもよい。
- ナレッジベースに接続できないとき（Web 版やローカル接続できないクライアントなど）は、そのことを伝え、書き込む予定だった内容を示す。
- クライアント内蔵のメモリ機能には個人の好みなど短期的な情報だけを置く。JOPT の業務記録は必ずこのナレッジベースに書き、「内蔵メモリに記憶した」で書き込みの代わりにしない。

## デスクトップ AI の接続

- ローカル MCP に対応するデスクトップ AI を同じ社員個人のナレッジベースに接続し、プロジェクト、ルートフォルダ、ツール権限をそれぞれ確認する。現在の試行プロジェクト名は work-status-preview。他の社員の PC にインストールする場合は、インストール設定に従ってプロジェクトとフォルダを決める。
- 書き込みツール bm_write と bm_edit は常時許可にし、削除や移動などその他のツールは承認制のままにする。
- 各クライアントは自身の常設指示で JOPT Memory のワークフローを有効にする（Claude Code：CLAUDE.md、Codex：AGENTS.md、Claude デスクトップの通常チャット：アカウントの「指示」）。検索、読み取り、許可された書き込みをそれぞれ検証する。ローカル接続に対応しているかは、クライアントごとの実機確認を基準にする。
- ローカルのナレッジベースに接続できない AI には手動で取り込む。利用者がローカルから必要な JOPT の Markdown を書き出すかフォルダをコピーし、会社が利用を認めた AI にアップロードする。書き出した日付を記録し、版を判断できるようにする。アップロードはその時点のスナップショットであり、元のナレッジベースはローカル接続できるデスクトップ AI で更新するのを基本とする。
- ローカルのナレッジベースを正本とする。正式ノートは、端末に設定したバックグラウンド処理が会社指定の共有ドライブへ一方向にまとめてコピーする。業務ごとに AI が個別にアップロードする必要はない。会社が承認したクラウドクライアントは共有ドライブのコピーを参照できる。既存の Drive 原本リンクは引き続き成果物の出典として使う。

## 試行の検収

1. デスクトップ AI が新しい会話で引き継ぎ対象の作業を行う。指示には業務の要件だけを書き、「保存」「記録」とは言わない。実際に追加・更新されたローカル Markdown、既存ノートへの追記になっているか、回答の最後に記憶ステータス行があるかを確認する。対照として一般的な質問も 1 つ出し、誤って書き込まないことを確認する。
2. 同じナレッジベースに接続した別のデスクトップ AI が、新しい会話で自然な質問をして、結果・次のアクション・原本の場所を読み返せることを確認する。
3. ローカルから選んだ Markdown を、ローカル接続できない AI に取り込み、スナップショットの内容を引き出せること、PC 内のパスと社内原本リンクのアクセス可否を区別できることを確認する。書き出した Markdown を使って、別の PC でインデックスを再構築できることを確認する。
