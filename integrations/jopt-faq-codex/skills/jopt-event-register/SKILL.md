# 大会情報登録

登録・更新を依頼されたら、[登録手順と業務ルール](references/workflow.md) を読む。質問や説明だけの依頼では保存しない。利用者の最新の明示的な業務指示を優先する。

MCP `jopt_faq_events` が利用できれば `get_workflow_rules` と `get_registration_task` から最新の規則・依頼内容を取得する。未接続なら同梱の手順と [業務ルール](references/rules.json) で進める。

資料の読み取りは同僚本人のGoogle連携またはログイン済みブラウザー、保存はAppの通常の大会編集画面で行う。利用者にJSONの生成や貼り付けを求めない。MCPにGoogleのアクセス権があると説明しない。

登録の依頼が保存までを含む場合、根拠のある項目は保存と再読み込みの照合まで実行する。既存の同じ大会を更新し、新規は非表示で作成する。未確認項目で既存値を消さない。矛盾の残る項目は保留して質問し、他の項目を進める。

ポータルのスマートチップは実際のURLまで確認する。別の受付ポータルへの参照も比較する。予約の回答用シートから関連フォームの編集画面まで進み、本届の申込締切と必要な受付終了設定を読む。申込者の回答や個人情報は取得しない。

保存完了の表示に続き、Appを再読み込みして大会ID、各値、大会数、表示状態を確認する。値が消えるなどの不具合は報告し、追加の依頼なしにソースコードを変更しない。Harness・LINEへの公開、フォームやポータルの編集、Slack調査は含まない。
